"旧版" vs "新版" — 到底是什么关系？

同一个项目里两套代码的由来和对比

旧版：public/ 目录

启动方式：node server.js → localhost:3000

技术栈：纯 HTML + CSS + 原生 JS (零依赖)

数据：JSON 文件读写 (data/db.json)

✅ 功能完整（全都有 UI）：

  • 智能工作台 — 对话界面
  • 我的智能体 — CRUD + 测试
  • 智能体开发 — 配置编辑器
  • 知识库 — 文档上传
  • 模型管理
  • 连接器与工具
  • 数据报表

⚠️ 但是没有数据库、没有流式响应、没有类型安全

新版：web/ + api/ 目录

启动方式：uvicorn + vite → :8000 + :5173

技术栈：React + TypeScript + Vite / FastAPI + SQLAlchemy

数据：SQLite/PostgreSQL 持久化

✅ 架构升级到位：

  • SSE 流式对话（打字机效果）
  • SQL 持久化 + ORM
  • TypeScript 类型安全
  • Docker 生产级部署
  • OpenAI 兼容模型接入

⚠️ 但只实现了核心对话功能，其他页面全空

简单来说

旧版是功能完整的原型（能看全貌但技术简朴），
新版是正在迁移中的升级（技术扎实但功能不全）。

项目当前状态 ≈ 新版的骨架 + 流式对话核心链路 已经跑通，
其他所有页面和功能还需要从旧版"搬运升级"过来。
