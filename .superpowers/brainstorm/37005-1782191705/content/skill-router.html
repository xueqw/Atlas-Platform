Skill Router 由谁承担？

Planner Agent 内置路由能力，Skill Registry 提供地址簿

路由机制拆解 — 两个阶段的协作

用户输入: "帮我分析这份销售数据并生成周报"

┌─ Planner Agent (路由器) ─────────────────────┐
│ [理解] 意图: 数据分析 + 报告生成 │
│ [拆分] Step1: 数据清洗; Step2: 趋势分析;
│ Step3: 生成周报 │
│ [匹配] 查 Skill Registry → │
│ Step1 → data_cleaning_skill │
│ Step2 → trend_analysis_skill │
│ Step3 → report_gen_skill │
│ [调度] Step1→Step2 串行, Step3 依赖Step2 │
└──────────────────────────────────────────┘

Planner 发出调度指令 ↓

┌─ Skill Registry (地址簿) ────────────────────┐
│ data_cleaning_skill → worker_01 │
│ trend_analysis_skill → worker_02 │
│ report_gen_skill → worker_03 │
│ + MCP 动态发现的外部 tools/skills │
└──────────────────────────────────────────┘

Skill Workers 并行/串行执行 ↓

路由 = 匹配 + 调度，都在 Planner 内

路由子任务 做什么 由谁做 方式
🔍 发现 有哪些可用的 skill/工具 Skill Registry + MCP 静态注册表 + MCP 服务发现
🧠 匹配 用户的意图该用哪个 skill Planner Agent LLM 语义匹配 + 意图识别
🔗 编排 多个 skill 的执行顺序/依赖 Planner Agent DAG 依赖图生成
📡 调度 把任务发送给具体 worker 执行 Planner Agent 事件驱动/消息队列
⚡ 执行 真正干活 Skill Workers MCP Server / Python函数 / API

结论

Skill Router ≠ 一个独立组件，而是 Planner Agent 内建的调度能力。

类比：Planner 是项目经理，Skill Registry 是通讯录，Skill Workers 是团队成员。
项目经理自己决定"找谁、按什么顺序"——不需要再设一个"找谁专员"。

所以最终架构就是 三层：

Workflow (边界) → Planner Agent (路由+编排) → Skill Workers (执行)
